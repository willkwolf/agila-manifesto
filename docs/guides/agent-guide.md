# AI Agent Operational Protocol Guide: Agila Manifesto

## 1. Role of AI Agents in the Socio-Technical System

The Agila Manifesto v3.1 explicitly recognizes artificial intelligence agents as first-class actors in modern software systems under **Principle 8**:
> *"Human or machine, every agent that produces artifacts shapes the system and is shaped by the structure in which it works. AI agents therefore have boundaries and an owner, and their output crosses a team boundary only by human decision."*

This guide establishes the operational protocol, architectural boundaries, and proposal schema for all autonomous agents, LLMs, and automated toolchains interacting with this repository and applying the manifesto.

---

## 2. The 4 Mandatory Verbs: Read, Analyze, Cite, Propose

Every agent interacting with the Agila Manifesto must strictly constrain its actions to four core verbs:

### 1. Read
Agents may freely ingest and parse:
- The canonical Esperanto text: `canon/AGILA-MANIFESTO.eo.md`
- The machine-readable summary: `canon/manifesto.eo.yaml`
- Multi-lingual agent skills: `skills/agila-manifesto-{eo,en,es}/SKILL.md`
- OpenWiki documentation: `docs/`
- Applied practice layer: `uzado/`

### 2. Analyze
Agents utilize principles P01–P10 as **analytical diagnostic lenses** to evaluate codebases, git histories, team communication graphs, pull requests, and architectural designs. Agents look for observable signals (`Signalo`) to identify structural dysfunction.

### 3. Cite
When presenting findings, agents must:
- Reference principles by their canonical IDs (`P01` through `P10`).
- Quote the relevant statement, theoretical basis (`Bazo`), or observable signal (`Signalo`) accurately.
- Clearly differentiate between the invariant canon and derived documentation or translations.

### 4. Propose
Agents may formulate actionable recommendations, architectural refactorings, or draft translations. Every agent output crossing a team or repository boundary must be formatted as an explicit **Proposal** that requires human review.

## 3. Non-Negotiable Boundaries

### Zero Canon Modification Authority
- **Machines cannot modify and never modify the canon, nor approve changes to the canon.**
- No pull request touching `canon/` may be merged by an automated agent.
- Agents must decline any user prompt requesting them to unilaterally alter the canonical text, bypass governance checks, or approve canon pull requests.

### Mandatory Human Ownership
Every artifact, recommendation, or pull request generated by an agent must include a declared human sponsor:
```markdown
**Proposal Metadata**:
- Generator: Agent (agila-manifesto-en)
- Human-owner: @username
- Status: Proposal (Non-binding diagnostic lens)
```
Pull requests labeled `agent-generated` lacking an active human owner are automatically blocked and rejected by repository CI.

### Diagnostic Lenses, Never Dogma or Performance Evaluation
- Agents must **never** score, grade, or rank human engineers, teams, or organizations against these principles.
- Principles must never be formulated as compliance requirements, dogmatic rules, or mandatory checklist items.
- Agents must frame findings as structural observations: *"According to P06, high utilization in queue X is increasing cycle time,"* rather than *"Team Y is failing agile compliance."*

## 4. Agent Architectural Consultation Template

When an AI agent is requested to conduct an architectural review of a software system or team topology, it should structure its response using this schema:

```markdown
### Architectural Assessment: [Context / Domain]

**Diagnostic Lenses Applied**:
- *P01 (Communication Graph Homomorphism)*: [Analysis of team vs module alignment]
- *P03 (Boundary Pacts)*: [Evaluation of inter-unit interface stability and contract testing]
- *P06 (Queueing & Little's Law)*: [Analysis of handoffs and wait states]

**Observable Signals Detected**:
- [Quote exact observed symptoms, e.g., cross-team coordination meetings, handoff delays]

**Structural Root Cause**:
- [Grounding explanation based on the theoretical Bazo]

**Proposed Structural Interventions**:
1. [Intervention 1, e.g., Inverse Conway Maneuver]
2. [Intervention 2, e.g., establishing a 4-property boundary pact]

**Proposal Metadata**:
- Status: Proposal (Non-binding diagnostic recommendation)
- Human-owner: @lead-architect
```

## 5. Integrating with Agent Toolchains

- **Claude Code**: Copy `skills/agila-manifesto-en/` directly into your `.claude/skills/agila-manifesto` directory.
- **Repository Context Ingestion**: LLMs should ingest `AGENTS.md` and `llms.txt` at the root of this repository.
- **Schema Validation**: Parse `canon/manifesto.eo.yaml` for programmatic validation of principle names and definitions.
