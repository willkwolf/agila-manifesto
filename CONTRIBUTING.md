# Contributing to the Agila Manifesto

Welcome! The **Agila Manifesto v3.1** is an international, open-source socio-technical framework designed for collaborative use by humans and AI agents.

Whether you are an architect submitting an organizational case study, a linguist translating the principles, or a practitioner submitting a counterexample, your contribution is valuable.

---

## Non-Negotiable Core Principles

1. **One Canon in Esperanto**: The canonical text in `canon/AGILA-MANIFESTO.eo.md` is the sole authoritative standard. All other languages are explicitly derivative.
2. **Human Sovereignty over Canon**: Machines read, analyze, cite, and propose; **only humans approve and modify the canon**.
3. **No Dogma**: Principles are analytical lenses to diagnose socio-technical friction, never commandments, compliance checklists, or developer grading schemes.
4. **"A Counterexample is a Gift"**: If a principle fails in your context, reporting that failure helps refine the scientific boundary of the framework.

---

## Five Contribution Pathways

### 1. Proposing an Evolution to the Canon (Tier 1: Fundamento)
Changes to `canon/` govern the core manifesto and adhere to strict Tier 1 governance:
- **How to Submit**: Open an issue using the [Canon Proposal Template](.github/ISSUE_TEMPLATE/01_canon_propono.yml).
- **Mandatory Requirements**:
  - Proposed Esperanto text.
  - Theoretical Base (`Bazo`) and grounding status (Theorem, Model, Empirical Tendency, Interpretation).
  - Observable Signal (`Signalo`).
  - Empirical analysis addressing potential counterexamples.
  - Designated human sponsor (`Human-owner: @username`).
- **Deliberation Process**:
  - Must remain open for public deliberation for **at least 14 calendar days**.
  - Requires approval from **at least 2 human stewards**.
  - Must resolve all open, substantiated counterexamples.

### 2. Submitting a Counterexample ("A Counterexample is a Gift")
Scientific progress happens when models are challenged by empirical evidence:
- **How to Submit**: Open an issue using the [Counterexample Template](.github/ISSUE_TEMPLATE/02_kontrauekzemplo.yml).
- **Format**:
  - Identify the principle challenged (P01 through P10).
  - Describe the concrete organizational or technical context.
  - Detail why the expected outcome did not occur or where perverse incentives arose.
  - Propose refinements to the boundary conditions or wording.

### 3. Adding a New Language Translation (Tier 2: Tradukoj)
We seek to expand translations across global languages:
- **Priority Languages**: Check [i18n/STATUS.md](i18n/STATUS.md) for sought-after languages (`zh`, `hi`, `ar`, `pt`, `fr`, `ru`, `ja`, `de`, `id`, `bn`).
- **How to Start**:
  1. Open an issue using [New Translation Template](.github/ISSUE_TEMPLATE/03_nova_traduko.yml).
  2. Copy `i18n/_template/SKILL.template.md` to `skills/agila-manifesto-<lang>/SKILL.md`.
  3. Populate frontmatter metadata: `lang`, `canon_version: "3.1"`, `canon_sha256: "44dd1dc966874fceea8d53d9ac312397b1fcb5e9f51919bbe0e71b19d027c470"`, `status: "draft"`, `translators`.
  4. Translate all 10 principles preserving IDs `P01` through `P10` and include the mandatory derivative disclaimer.
  5. Run `python scripts/validate.py --update` to verify formatting and update tables.

### 4. Correcting an Existing Translation
To refine translations in `skills/agila-manifesto-eo/`, `skills/agila-manifesto-en/`, or `skills/agila-manifesto-es/`:
- Open an issue using [Translation Fix Template](.github/ISSUE_TEMPLATE/04_korektu_tradukon.yml) or submit a pull request.
- Ensure the translation preserves the semantic fidelity of the canonical Esperanto text.

### 5. Contributing Practical Case Studies to Uzado (Tier 3)
The `uzado/` layer collects field reports, architectural patterns, and anti-patterns:
- **How to Submit**: Open an issue using [Uzado Contribution Template](.github/ISSUE_TEMPLATE/05_uzado_kontribuo.yml) or submit a PR adding markdown files under `uzado/patterns/` or `uzado/anti-patterns/`.
- **Review**: Requires only 1 approving review from a maintainer or designated peer reviewer.
- **Rules**: Must be non-commercial; avoid vendor pitches or product endorsements.

## AI Agent Contribution Protocol

We encourage the use of AI agents and coding assistants to analyze architectures, translate texts, and draft documentation. However, all agent interactions must adhere to this protocol:

1. **Tagging**: Pull requests authored or generated by automated agents must apply the `agent-generated` label.
2. **Mandatory Human Owner**: Every agent-generated PR must include `Human-owner: @username` in the description body. This human accepts full responsibility for the PR contents.
3. **No Machine Self-Approval**: Automated bots cannot approve or merge pull requests. PRs touching `canon/` will be blocked unless explicitly reviewed and approved by human stewards.
4. **Lenses, Not Dogma**: Agent prompts must never command agents to grade, score, or punish human teams using the Agila Manifesto principles.

## Local Verification & Quality Checks

Before submitting any pull request:
1. Ensure Python 3.10+ is installed.
2. Run validation in check mode:
   ```bash
   python scripts/validate.py --check
   ```
3. If modifying translations or language skills, synchronize the status tables:
   ```bash
   python scripts/validate.py --update
   ```
4. Run the test suite:
   ```bash
   python -m unittest discover -s tests -p "test_*.py"
   ```
