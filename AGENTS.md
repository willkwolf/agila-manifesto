## 2. Non-Negotiable Agent Protocol: Read, Analyze, Cite, Propose

Every automated agent, coding assistant, and LLM interacting with this repository must operate strictly under the following four verbs:

1. **Read**: Ingest the canonical Esperanto text in `canon/AGILA-MANIFESTO.eo.md` and machine-readable definitions in `canon/manifesto.eo.yaml`.
2. **Analyze**: Use principles `P01` through `P10` as **analytical diagnostic lenses** to evaluate team topologies, software architectures, communication bottlenecks, and codebases.
3. **Cite**: Reference principles by their canonical IDs (`P01` to `P10`), quoting the exact principle title, theoretical basis (`Bazo`), or observable signal (`Signalo`).
4. **Propose**: Generate actionable recommendations, refactorings, or draft translations. Every agent-generated artifact must be explicitly marked as a non-binding proposal.

---

## 3. Sovereign Human Governance & Agent Boundaries

1. **Zero Canon Modification Authority**:
   - Machines cannot modify and never modify the canon, nor approve changes to the canon.
   - All authority to modify, approve, or merge changes to `canon/` belongs strictly to human stewards.
   - Any pull request touching `canon/` that is generated or approved by an agent without human signoff will be automatically blocked by repository CI.
2. **Mandatory Human Ownership**:
   - Every proposal or pull request generated by an agent must specify an active human sponsor via `Human-owner: @username`.
   - Proposals without an identified human owner will not be merged.
3. **Diagnostic Lenses, Never Commands or Scoring Dogma**:
   - Agents must **never** treat the manifesto principles as mandatory commandments, rigid compliance checklists, or performance scoring rubrics.
   - Agents must never evaluate, rank, or score human developers or teams against these principles.
   - Principles are descriptive laws of nature and design tendencies, intended to uncover structural friction, not to punish engineers.

---

## 4. Proposal Schema for Agents

When generating an architectural assessment or recommendations artifact, format your output according to this schema:

```markdown
### Architectural Assessment: [Subject Area]

**Lenses Applied**:
- *P01 (Homomorphism)*: [Module boundaries reflect team communication paths]
- *P06 (Queueing & Little's Law)*: [Bottlenecks arise at team handoffs]

**Findings**: [Observed friction and structural symptoms]

**Recommendation**: [Proposed architectural or organizational adjustment]

**Proposal Metadata**:
- Status: Proposal (Non-binding diagnostic lens)
- Human-owner: @lead-architect
```
